# Live Render verification and corrected attempts

The complete synthetic demo was deployed on 26 November 2026 with the user-authorized Render CLI. All three web services use the free plan in Singapore. No paid resources were purchased and no unrelated service or datastore was restarted.

- Initial API deploy failed with PostgreSQL SQLSTATE 42501 during one-time provisioning. PostgreSQL 16+ requires explicit SET ROLE membership to create a database owned by a newly created role. The bootstrap now grants that membership to the provisioner. A real local check using a non-superuser CREATEDB/CREATEROLE provisioner passed; the next Render deployment applied all six migrations and seeded the separate MediCore database. Deployment IDs and safe runtime events are retained in render-deployment.json and render-runtime.log.
- The one-time privileged DATABASE_BOOTSTRAP_URL was removed from Render and the start command restored to the ordinary API entry point. A new deployment and subsequent restart were verified. Runtime credentials use the separate MediCore role; there are no Render control-plane tokens in application environment variables.
- The first live workflow harness omitted required emergency-contact and address fields in its registration fixture. The API correctly returned 400. The fixture was completed to match the shared validation schema; its expected 201 and patient-only role assertions were retained. The original five-check attempt is kept in live-initial-attempt.json. The final workflow run passed all 57 checks.
- The first live browser run passed 46 of 48 cases. One dashboard received transient 502 responses while the API redeployed. A booking assertion also exceeded its five-second implicit wait while availability remained in flight. The browser test now waits for network completion and explicitly selects a future available slot returned by the real API. The error assertions were retained. Against the stable deployment, all 48 cases passed, with no retries or skips. Initial results are kept in live-playwright-initial.json and final results in live-playwright-results.json.
- A controlled restart affected only the MediCore API. A preexisting authenticated session remained valid and the newly created paid invoice remained available after a fresh process was observed. See live-restart-persistence.json. Shared PostgreSQL and Redis were not restarted or subjected to outage tests.

The final results are evidence of these synthetic cases, not certification of production availability or regulatory compliance. Off-host cloud backup/restore, retention archival, protected staging releases, actual peer approval and a separate migration owner remain incomplete. Free resources share workspace instance hours, sleep when idle and depend on a PostgreSQL instance expiring 25 December 2026 at 19:00 UTC.
